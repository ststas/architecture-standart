### **Решение**

Для MVP выбирается разделённая схема передачи ставок:

- внутренний кол-центр банка получает ставки через доработку собственной системы кол-центра и внутренний API сервиса ставок;
- партнёрский кол-центр получает актуальные базовые ставки в виде файла, который банк автоматически отправляет на согласованный групповой e-mail;
- персонализированные ставки и клиентские данные партнёрскому кол-центру не передаются.

#### Контекст решения

В контексте решения участвуют:

- оператор внутреннего кол-центра банка, который консультирует клиента по актуальным депозитным ставкам;
- оператор партнёрского кол-центра, который консультирует клиентов по файлу базовых ставок;
- АБС / модуль ставок как системный источник ставок;
- сервис ставок, который предоставляет актуальные ставки внутренним банковским системам;
- система кол-центра банка, в которой появляется экран просмотра ставок;
- сервис файлового экспорта, который формирует файл ставок для партнёра;
- почтовый сервис банка, который отправляет файл на согласованный адрес партнёрского кол-центра.

#### Основные интеграции

- АБС / модуль ставок передаёт актуальные ставки в сервис ставок или предоставляет их через согласованный внутренний интерфейс.
- Система кол-центра банка запрашивает актуальные базовые ставки у сервиса ставок по внутреннему API.
- Сервис файлового экспорта получает актуальные базовые ставки из сервиса ставок.
- Сервис файлового экспорта формирует XLSX/CSV-файл ставок по расписанию и при внеплановом изменении ставок.
- Почтовый сервис банка отправляет файл ставок на согласованный e-mail партнёрского кол-центра.
- Статусы формирования и отправки файла фиксируются в журнале рассылок и используются для мониторинга.

#### Логика выбора решения

Для внутреннего кол-центра выбирается API-интеграция, потому что система кол-центра находится в банковском контуре и может использовать внутренний сервис ставок. Это позволяет оператору видеть актуальные ставки прямо в рабочем интерфейсе, не переключаясь на XLS-файлы и ручные справочники.

Для партнёрского кол-центра выбирается файловая e-mail-рассылка на согласованный групповой адрес. Партнёр работает во внешней информационной системе, готов получать ставки в виде файлов и не может оперативно подключиться к API банка. Автоматическая отправка файла по e-mail минимизирует доработки партнёра и снижает риски внешней интеграции для MVP.

Персонализированные ставки не включаются в MVP для партнёрского кол-центра, потому что для этого потребовались бы идентификация клиента, передача клиентских данных, ролевая модель доступа, аудит просмотров и более строгая модель информационной безопасности. В MVP партнёру передаются только базовые справочные ставки.

### **Альтернативы**

| Альтернатива                                                   | Причина отказа                                                                                                                                |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Подключить партнёрский кол-центр к API сервиса ставок          | Требует доработки внешней системы партнёра, сетевой интеграции, авторизации, аудита и сопровождения внешнего API. Для MVP это избыточно.      |
| Предоставить партнёру доступ к Google Sheets / внешней таблице | Быстро организационно, но требует согласования внешнего SaaS, управления доступами и контроля выноса банковской информации за контур банка.   |
| Сделать партнёрский веб-портал ставок                          | Потенциально удобно как целевое решение, но требует разработки, авторизации, эксплуатации внешнего канала и поддержки пользователей партнёра. |
| Отправлять ставки партнёру вручную                             | Быстро на старте, но высок риск человеческих ошибок, несвоевременной отправки и отсутствия нормального контроля актуальности.                 |
| Передавать партнёру персонализированные ставки                 | Выводит за рамки MVP: нужны клиентские данные, идентификация клиента, аудит доступа и дополнительные требования ИБ.                           |
| Оставить консультации только во внутреннем кол-центре банка    | Не снижает риск перегрузки внутреннего кол-центра после маркетинговой кампании.                                                               |

**Недостатки, ограничения, риски**

- E-mail-рассылка не гарантирует, что операторы партнёра сразу начнут использовать последнюю версию файла.
- Есть риск консультации по устаревшему файлу, если письмо не доставлено, попало в спам или не было обработано партнёром.
- Необходимо согласовать адреса получателей, регламент обновления, формат файла и ответственность за использование актуальной версии.
- Решение не даёт партнёру персонализированные ставки и не позволяет обслуживать сценарии, где нужно знать условия конкретного клиента.
- При изменении структуры ставок потребуется синхронно обновлять формат файла и инструкции для партнёра.
- Если сервис ставок недоступен, система кол-центра банка не сможет получить актуальные данные, а файловая рассылка может быть сорвана.
- Автоматическая рассылка требует мониторинга, алертов и ручного сценария повторной отправки.
- Целевое развитие может потребовать партнёрского портала или защищённой внешней интеграции, если объём консультаций и требования к актуальности вырастут.
