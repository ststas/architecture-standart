### **Решение**

Для MVP выбирается архитектура с отдельным контуром обработки депозитных заявок между клиентскими каналами и АБС. Сайт и интернет-банк не должны напрямую нагружать АБС массовыми онлайн-запросами. АБС остаётся системой учёта, подтверждения условий депозита, хранения договорной информации и открытия депозита.

#### Контекст решения

В контексте решения участвуют:

- новый клиент, который работает с сайтом и затем проходит идентификацию в отделении;
- действующий клиент, который работает через интернет-банк;
- менеджер кол-центра, который обрабатывает заявки с сайта;
- менеджер бэк-офиса депозитов, который подтверждает условия депозита в MVP;
- бэк-офис кредитных продуктов, который участвует в работе со ставками и риск-данными;
- сайт, интернет-банк, АБС, система кол-центра, SMS-шлюз и телеком-оператор.

#### Контейнеры решения

В MVP предлагается выделить следующие основные контейнеры:

| Контейнер                          | Назначение                                                                                                                                                                        |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сайт                               | Показывает список депозитов и актуальные ставки, принимает заявку нового клиента с Ф. И. О. и телефоном.                                                                          |
| Интернет-банк                      | Показывает депозиты, актуальные и персонализированные ставки; принимает заявку действующего клиента на открытие депозита.                                                         |
| Сервис обработки депозитных заявок | Принимает заявки из сайта и интернет-банка, хранит статусы, передаёт заявки на обработку менеджерам и в АБС контролируемым способом.                                              |
| БД заявок                          | Хранит заявки, статусы обработки, технические идентификаторы и результаты взаимодействия с внешними системами.                                                                    |
| Сервис ставок / модуль ставок      | Предоставляет актуальные и персонализированные ставки клиентским каналам, заменяя ручное использование XLS-файлов как единственного источника ставок.                             |
| АБС                                | Остаётся системой учёта депозитов, договоров, подтверждения условий и открытия депозита. В АБС также целесообразно реализовать управление ставками и процесс согласования ставки. |
| Система кол-центра                 | Позволяет менеджеру кол-центра видеть заявки с сайта и фиксировать результат звонка клиенту.                                                                                      |
| SMS-интеграция                     | Использует существующий SMS-шлюз для подтверждения операции СМС-кодом и отправки уведомлений клиенту.                                                                             |

#### Основные интеграции

- Сайт передаёт заявку нового клиента в сервис обработки депозитных заявок по защищённому каналу.
- Интернет-банк получает ставки из сервиса ставок и передаёт заявку в сервис обработки депозитных заявок после подтверждения СМС-кодом.
- Сервис обработки заявок хранит состояние заявки и передаёт её в АБС контролируемо, чтобы не создавать пиковую нагрузку на базу АБС.
- Менеджер бэк-офиса депозитов подтверждает условия депозита в АБС.
- АБС передаёт статус подтверждения ставки и открытия депозита в сервис обработки заявок; MVP-контур инициирует СМС-уведомления через SMS-интеграцию.
- Система кол-центра получает заявки с сайта или имеет доступ к ним для обработки звонка новому клиенту.
- Система кол-центра передаёт результат звонка и особые условия в сервис обработки заявок.
- Сервис ставок предоставляет актуальные ставки сайту, интернет-банку и внутренним участникам процесса.

#### Логика выбора решения

Решение разделяет клиентские каналы, обработку заявок и АБС. Это снижает нагрузку на АБС, которая уже перегружена и масштабируется только вертикально. Для MVP сохраняется ручное подтверждение условий менеджером бэк-офиса, поэтому решение не требует полной автоматизации процесса открытия депозита.

Ставки выносятся из XLS-файлов в системный контур. Предпочтительный вариант - реализовать управление ставками и согласование условий в АБС, поскольку текущий процесс уже завязан на АБС и бэк-офис работает в ней. При этом клиентские каналы должны получать ставки через отдельный сервисный интерфейс или кэшируемый слой, а не напрямую обращаться к базе АБС.

Для технологий используются существующие компетенции банка: MS SQL, Oracle, Java/Spring Boot, .NET/ASP.NET MVC. Kafka рассматривается как перспективный вариант для событийной интеграции, но не закладывается как обязательная зависимость MVP из-за несовместимости текущей версии интернет-банка.

### **Альтернативы**

| Альтернатива                                                         | Причина отказа                                                                                                                        |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Реализовать весь новый процесс только в АБС                          | Увеличивает нагрузку на уже перегруженную БД АБС и делает клиентские каналы жёстко зависимыми от АБС.                                 |
| Подключить сайт и интернет-банк напрямую к API АБС                   | Противоречит требованию минимизировать прямую работу интернет-банка с API АБС и повышает риск деградации АБС при росте онлайн-заявок. |
| Полностью автоматизировать открытие депозита без менеджера бэк-офиса | Не соответствует MVP: на первом этапе условия подтверждает менеджер бэк-офиса.                                                        |
| Сразу перевести весь интернет-банк на микросервисную архитектуру     | Слишком большой объём изменений для MVP; целесообразно ограничиться контуром открытия депозитов.                                      |
| Обязательная доработка SMS-функционала ядра подрядчиком              | В задании указано, что такой доработки лучше избежать; предпочтительнее реализовать бизнес-функционал силами команды банка.           |
| Сразу внедрить Kafka как обязательную интеграционную шину            | Kafka перспективна, но текущая версия интернет-банка несовместима с ней, поэтому для MVP это создаёт лишний риск.                     |

**Недостатки, ограничения, риски**

- В MVP сохраняется ручная обработка заявки менеджером бэк-офиса, поэтому процесс не будет полностью автоматическим.
- Для новых клиентов требуется очная идентификация в отделении; сайт не сможет завершить открытие депозита полностью онлайн.
- АБС остаётся критичной системой процесса, а её база уже перегружена и масштабируется только вертикально.
- Требование доступности 99,9% может потребовать доработок инфраструктуры интернет-банка, так как сейчас он работает в одном ЦОД на одной группе серверов.
- Если сервис заявок будет недоступен, клиентские каналы не смогут принимать новые заявки; требуется отказоустойчивое развёртывание.
- Если справочник ставок будет несогласован с АБС, клиент может увидеть ставку, которую бэк-офис не подтвердит.
- Интеграция с SMS-шлюзом критична для подтверждения операций и уведомления клиента.
- Использование Kafka в целевой архитектуре потребует отдельной совместимости с интернет-банком или адаптерного слоя.
